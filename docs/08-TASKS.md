## 0. 发布边界与关键路径

V1 的目标是可上架、可收费、可真实诊断的 P0 产品，不包含自定义仪表盘、数据录制/回放、适配器商城、单次解锁、社区或推荐奖励。

**关键路径：**

`脚手架 → 协议纯函数 → 模拟连接 → 本地诊断纵向切片 → 云与身份 → 订阅权益 → AI 诊断 → 报告/保养 → 真车与商店验证`

| 计划周 | 阶段 | 里程碑验收 |
|---|---|---|
| 第 1–2 周 | 0–1 | 工程可运行；协议纯函数和 fixtures 通过 |
| 第 3–4 周 | 2–3 | 模拟器走通连接→读码→实时数据→清码 |
| 第 5–6 周 | 4–5 | 本地 App 纵向切片完成；云端 RLS/同步可验证 |
| 第 7–8 周 | 6–7 | 购买/权益→AI→费用估算闭环完成 |
| 第 9 周 | 8 | 报告、保养与合规 P0 完成 |
| 第 10–12 周 | 9 | 多适配器/真车/美国内测与双平台上架 |

## 执行规则（给 Codex）

1. 严格遵守显式依赖；无依赖的任务可并行，但不得绕过阶段验收门。
2. 阶段 1、2、3、6、7 先写失败测试，再实现；协议 fixtures 与安全规则必须进入回归套件。
3. `T-00-01` 初始化 Git 后，每个任务至少一个范围清晰的提交；提交格式：`T-xx-xx: 标题`。
4. 每项 DoD：PRD 验收通过、相关自动化测试通过、错误/空/加载状态齐全、付费边界正确、必要埋点已验证、无密钥或敏感日志。
5. 自动化通过不代表真车、第三方账号、购买沙盒或商店审核已验证；交付时必须分开报告。
6. 涉及车辆安全的结论采用确定性服务端规则；LLM 不能单独决定 critical 降级、免责声明或数据来源。
7. 文档冲突时暂停该实现，先更新权威文档并取得确认；不得在代码中自行选择一套隐藏假设。
